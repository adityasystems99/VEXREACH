# Known Issues, Limitations & Open Risks (`KNOWN_ISSUES.md`)

This file tracks unresolved technical limitations, open security questions, and known design constraints—never hiding gaps behind marketing wording.

---

| ID | Category | Description | Severity | Mitigation / Plan |
| :--- | :--- | :--- | :--- | :--- |
| **`KI-01`** | Traffic Analysis | Dual-ended passive observation (`Client↔Entry` + `Exit↔Destination`) can correlate request timing and cell volume despite 3-hop AEAD. | **High (Fundamental)** | Documented honestly as non-defeated in `v0.1`; future mix delays/cover padding would be needed to resist timing correlation. |
| **`KI-02`** | Collusion / Sybil | A single operator running multiple relays or controlling `Entry + Exit` breaks sender-destination separation. | **High** | Enforce operator-ID & `/24`/`/48` prefix separation in `Phase 6` route selector; directory governance remains required against Sybil operators. |
| **`KI-03`** | Packet Length / Hop Role | Nested `ChaCha20-Poly1305` strips `25B/hop` (`1B subcmd + 8B seq + 16B tag`) inside the `571B` max cell body (`582B` outer plaintext), revealing hop index (`1/2/3`) to adjacent honest relays in our 3-role topology. | **Medium (Design Trade-off)** | Acceptable for fixed `Entry → Middle → Exit` roles; variable `N`-hop anonymity requires Sphinx constant-size headers (`Deferred`). |
| **`KI-04`** | Transport | Multiplexing multiple circuits over a single TCP link can suffer head-of-line blocking under packet loss. | **Medium** | Measured in `Phase 8`; evaluate QUIC stream isolation only after TCP baseline metrics exist. |
| **`KI-05`** | SSRF / DNS Rebinding & Timeout | Exit DNS lookup followed by separate `TcpStream::connect(hostname)` risks TOCTOU DNS rebinding or stalled lookup hangs. | **Mitigated (`v0.1`)** | `DestinationPolicy::resolve_and_validate` validates every resolved IP once under `timeout(dest_timeout, ...)` (`SEC-201`) and passes `validated_addr` directly to `TcpStream::connect` (`SEC-204`). *(Remains limited to `resolved[0]` & OS resolver integrity per `SEC-205`.)* |
| **`KI-06`** | Implementation Scope | `v0.1` workspace (`protocol`, `crypto`, `network`, `relay`, `client`, `cli`), bare-metal Windows demo, 5-container Docker Compose stack (`12/12` E2E), live `kind` (`v1.32.2`) + Calico (`v3.29.1`) Kubernetes deployment (`12/12` traffic, `15/15` CNI policies, Pod restart/fail-closed/resilience tests), and live Prometheus/Grafana observability are **VERIFIED** (`54/54` Rust tests). Multi-node WAN clustering, Coordinator discovery (`Phase 11`), fuzzing (`cargo-fuzz`), and LLM integrations remain deferred beyond `v0.1`. | **Verified Local K8s/Calico; Multi-Node & Coordinator Deferred** | Tracked honestly across `ROADMAP.md`, `PROJECT_STATUS.md`, `docs/DAY_8_DEPLOYMENT_REPORT.md`, `docs/DAY_9_RESILIENCE_REPORT.md`, `docs/DAY_10_OBSERVABILITY_REPORT.md`, and `docs/DAY_8_10_INTEGRATED_REPORT.md`. |
| **`KI-10`** | Single-Replica Kubernetes Constraint | Relay Deployments (`entry`, `middle`, `exit`) are constrained to `replicas: 1` (`strategy: Recreate`) in `v0.1` because each relay owns an individual pinned static X25519 keypair and holds established circuits strictly in local Pod RAM (`ClusterIP` round-robin across distinct-key replicas triggers `Noise_IK` key mismatch, and Pod restarts terminate active circuits). | **Medium (v0.1 Architecture Limit)** | Horizontal relay scaling requires `StatefulSet` + per-Pod identities registered via Coordinator discovery in a future milestone. |
| **`KI-11`** | Inbound Nonce & Frame Cancellation Hardening | Under high concurrency or network packet slicing, link connections could previously desynchronize or exceed link nonce boundaries. Remediated under `SEC-701` (inbound nonce assert) and `SEC-702` (RAII mid-frame cancellation session poisoning). | **Mitigated (`v0.1 Day 7`)** | Fully covered with regression tests in `crypto_tests.rs` and `network_tests.rs`. |
| **`KI-07`** | OS Loopback Connect Latency | On Windows 11, connecting to an unbound loopback port waits ~`2.04s` before returning `WSAECONNREFUSED`, so low `destination_io_timeout_ms` (`<= 2s`) reports `RequestErrorCode::Timeout` instead of `ConnectFailed`. | **Low (Platform Behavior)** | Default `destination_io_timeout_ms` is `10_000` (`10s`; `3500ms`/`2500ms` in tests); documented in test and demo configs. |
| **`KI-08`** | Sequential Request Scope & Link Rekeying | `v0.1` executes one sequential bounded request per circuit (`Overlapping -> ProtocolError`) per `D-01`. Automated `3600s` / `1 GiB` Noise link rekeying (`D-09`) IS now implemented and verified in `LinkSession`/`LinkWriter`/`LinkReader`; HTTP/TLS end-to-end client wrapping & `v0.2` multiplexed streams remain future extensions. | **Link Rekey Mitigated (`v0.1`); Multiplexing Deferred** | Coordinated in-band `Noise` transport rekeying tested via crypto, TCP network, and 3-hop E2E tests (`40/40` suite). |
| **`KI-09`** | External Audit & Offline CVE Scan Pending | Classified internal security review completed ([SECURITY_REVIEW.md](./SECURITY_REVIEW.md)); external third-party audit, `cargo-fuzz`, and `cargo-audit`/`cargo-deny` advisory matching (tools absent offline) have NOT been executed. | **High (Pre-Production Gate)** | Treat strictly as a local engineering research prototype until formal external audit, fuzzing, and CVE scan complete. |
