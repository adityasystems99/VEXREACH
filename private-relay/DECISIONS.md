# Architectural Decision Record (`DECISIONS.md`)

Every major design choice for **Private-Relay** is logged here with rationale, alternatives rejected, consequences, and reversibility conditions.

---

| ID | Decision | Alternatives Considered | Rationale & Consequences | Status |
| :--- | :--- | :--- | :--- | :--- |
| **`D-01`** | **Bounded Request/Response Forwarding (`<= 64 KiB` request & response, `<= 140` chunks per message, associated via `RequestId`) over persistent bidirectional relay-link TCP connections** | Full bidirectional interactive TCP stream multiplexing (SOCKS5 + `SENDME`/window-credit flow control) | *Rationale:* Proves 3-hop crypto, return routing, Exit DNS, and SSRF policy cleanly in `v0.1` without TCP-over-TCP flow-control deadlock risk, while using persistent bidirectional TCP connections between adjacent peers (`Client↔Entry↔Middle↔Exit`). *Consequence:* Long-lived interactive application streams (`SSH`, media streaming) and `SENDME` window credits are deferred to `v0.2+`. `RequestId` + explicit chunk indexing preserve structural extensibility. | **Accepted (Approved 2026-11-26 for v0.1)** |
| **`D-02`** | **`Noise_IK` (link transport) + `Noise_NK` (telescopic hops) + nested `ChaCha20-Poly1305` inside fixed `600`-byte total on-wire Noise link frames (`2B` length prefix `== 598` + `582B` padded outer plaintext + `16B` Noise MAC = `600B`)** | Raw TLS 1.3 + Tor `AES-CTR` running digest; variable-length unpadded frames; legacy `602B` arithmetic draft | *Rationale:* Pure reviewed primitives via `snow` + RustCrypto; eliminates tagging/malleability bugs (`Poly1305` per hop) and X.509 cert friction in `v0.1`. *Arithmetic Correction (2026-11-26):* Reconciled prior `2 + 584 + 16 = 602B` mismatch so **complete on-wire outer frame = `600` bytes exact** (`2B outer_len == 598` + `582B` outer plaintext + `16B` Noise link tag). Outer plaintext encodes `2B real_len` + `<= 580B` cell (`9B` header + `<= 571B` body) + random padding to `582B`. *Consequence:* 3 nested onion hops consume `3 × (8B seq + 16B tag + 1B subcmd) = 75B`, leaving `496B` max `InnerPayload` (`9B` header + `<= 487B` fragment, fitting `64 KiB + 257B` target within `<= 136 <= 140` chunks) and revealing hop index inside outer Noise frames (`KI-03`). | **Accepted (Reconciled 2026-11-26 for v0.1)** |
| **`D-03`** | **Pure-Rust Crypto (`snow`, `chacha20poly1305`, `hkdf`, `zeroize`) over C FFI (`ring`/`openssl`)** | `ring`, `openssl` | *Rationale:* Smooth compilation on Windows MSVC (`rustc 1.93.1` + VS2022 `link.exe`) with zero external C SDK headaches. | **Accepted for v0.1** |
| **`D-04`** | **Static TOML Directory in `v0.1`; Evaluate Centralized vs. Federated Directory in `Phase 6`** | Building Axum + PostgreSQL Coordinator in Phase 1 | *Rationale:* Avoids premature distributed systems complexity; `Phase 6` will explicitly address single-coordinator route-partitioning trust risks via signed/federated directories before production use. | **Accepted** |
| **`D-05`** | **Single Parameterized `relay` Crate (`role = entry \| middle \| exit`)** | Three separate binaries/crates upfront | *Rationale:* Prevents duplicated socket/Noise/circuit code across 3 hops while preserving strict runtime role boundaries (`Exit` policy enabled only when `role = exit`). | **Accepted** |
| **`D-06`** | **Defer Live Kubernetes Deployments & Live LLM Credentials Until Explicitly Authorized** | Writing Helm/K8s manifests & live LLM clients upfront | *Rationale:* Protects architectural focus; future containers/configs remain K8s-friendly and LLM abstractions remain purely optional/mocked without touching security-critical relay paths. | **Accepted (Rule Lock)** |
| **`D-07`** | **End-to-End Per-Hop AEAD AAD Omits Link-Local `CircuitId` (`b"PRv1" \|\| version \|\| direction \|\| hop_index \|\| seq`)** | Binding link-local `circuit_id` (`C1`, `C2`, `C3`) inside end-to-end `ChaCha20-Poly1305` AAD | *Rationale:* Relays allocate `C2`/`C3` locally without exposing them to Client; binding `C2`/`C3` in end-to-hop AAD would break Client ↔ Middle/Exit tag verification. Link-local `circuit_id` integrity is enforced by each hop's authenticated `Noise_IK` link channel, while cross-circuit isolation relies on fresh per-circuit ephemeral `Noise_NK` + `HKDF-SHA256` keys (`K_fwd_i`, `K_bwd_i`) and explicit `[version, direction, hop_index, seq]` in AAD. | **Accepted (Security Correction 2026-11-26)** |
| **`D-08`** | **`Noise_NK` Hop Key Exporter Uses Transcript-Salted `HKDF-SHA256(salt = h_nk, ikm = c_seed \|\| r_seed)` Inside Encrypted Handshake Payloads** | Enabling `snow`'s `risky-raw-split` feature or rolling custom X25519 DH outside Noise | *Rationale:* `snow v0.9.6` hides the internal chaining key cleanly without raw split flags. Exchanging 32-byte OS CSPRNG seeds encrypted inside `msg1` (`es`) and `msg2` (`es, ee`) mixed with `snow::HandshakeState::get_handshake_hash()` guarantees forward secrecy, transcript binding, and symmetry across Initiator and Responder without touching unverified internals. *Reversibility:* Localized inside `crates/crypto/src/hop.rs` if future exporter APIs are adopted. | **Accepted (Day 2 Implementation 2026-11-26)** |
