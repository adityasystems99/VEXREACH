# Contributing to VEXReach

Thank you for your interest in contributing to VEXReach!

VEXReach is an open-source security intelligence platform where **correctness, explainability, and defensibility** take precedence over feature quantity.

---

## Core Engineering Principles

Before contributing code, please ensure you align with our core engineering tenets:
1. **Never suppress uncertainty**: If static analysis cannot determine reachability (e.g., dynamic dispatch, dynamic imports), the result must be explicitly marked as `under_investigation`. Never default to `not_affected`.
2. **Deterministic Security Policies**: AI/LLM models must never assign final security statuses. All VEX decisions must be generated by verifiable, deterministic rules.
3. **No Blind Shell Interpolation**: All external tool executions must use parameterized argument lists without shell injection hazards.
4. **Test Every Component**: Every bug fix requires a regression test. Every new feature requires unit and integration tests.

---

## Development Setup

1. Fork and clone the repository.
2. Ensure Python 3.12+ is installed.
3. Create a virtual environment:
   ```bash
   python -m venv .venv
   # Windows PowerShell:
   .venv\Scripts\Activate.ps1
   # Linux/macOS:
   source .venv/bin/activate
   ```
4. Install editable package with dev tools:
   ```bash
   pip install -e ".[dev]"
   ```
5. Verify test runner:
   ```bash
   pytest
   ```

---

## Submitting Pull Requests

1. **Create a topic branch**: `git checkout -b feature/my-feature-name`.
2. **Write tests**: Add unit tests in `tests/unit/` and integration tests in `tests/integration/`.
3. **Format and lint**:
   ```bash
   ruff check .
   ruff format --check .
   ```
4. **Ensure clean CI**: All automated tests must pass before review.
